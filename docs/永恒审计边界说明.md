## 修正理由（密码学完整性 > 逐文件 DNA 注释）

本仓包含**密码学证据工件**，它们的字节内容被规范（GADIC-PROV-MVP-001 v0.2.0）钉死：

| 文件 | 为什么不能加 DNA 注释 |
| --- | --- |
| evidence/*/manifest.json | 必须是精确 JCS（RFC 8785）规范字节；文件摘要 = 待签名摘要，加一行注释 → 签名验证必然失败 |
| evidence/*/signature-envelope.json | 同上，JCS 规范字节落盘 |
| evidence/transparency-log/events.jsonl | 每行 = leaf_data，Merkle 叶子 = SHA256(0x00‖JCS(event))，改字节 → 包含证明全断 |
| evidence/*/timestamp/token.tsr | RFC 3161 二进制令牌，本就非文本 |
| *.pem | 公钥数据，格式固定 |
| config/*.json、reports/*.json | JSON 按钩子自家规矩走"旁签"（钩子判据注释原文：JSON走旁签） |

## 替代完整性锚（比逐文件注释更强）

1. **代码与文档 26 个文本文件全部带独立 DNA**（`#龍芯⚡️` 标记，逐文件 lh_dna_generator 生成）。
2. **SHA256SUMS.sha256** 覆盖全部源文件（含本说明），`sha256sum -c` 可复验。
3. **证据工件由证据链自身锚定**：Merkle 检查点签名（日志密钥 Ed25519）+ 独立验证器重放——篡改任何一行 events.jsonl 都会被包含证明当场抓出（测试矩阵 T-013/T-014/T-016/T-017 实证）。
